# ORG_WORKFLOW_REPORT.md — Organization Mode QA Audit

**Audit type:** Independent QA (read-only code audit + targeted local evidence). No fixes applied.  
**Date:** 2026-11-06  
**Scope:** “Organization” mode — intended workflow steps 1–6.  
**Method:** Source inspection (`packages/desktop/src/renderer/pages/organization/**`, `packages/desktop/src/types/organization.ts`, preload/common/process searches), existing org unit tests run locally, A1 test-folder creation in `C:\Users\dell\AppData\Local\Temp\kilo\org-qa-test-folder`. UI-runtime behaviors (dialogs, canvas interactions, live agent execution, scheduler firing) are **UNVERIFIED** where no runtime evidence was available.

## 1. Summary

**Overall verdict: Not working** (for the intended end-to-end workflow). **Partially working** for local UI/data-model scaffolding.

1. Organization state is a **renderer-local model** persisted in `localStorage` (`useOrgStore.ts:43-49,89-136,147-150,162-167`), not a main-process/Electron DB org system. Default state is effectively a blank canvas (`defaultOrgSeed.ts:17-73`, `useOrgStore.ts:93-111` forces defaults on version bump).
2. **CEO folder analysis (step 1-2 of intended workflow) is missing.** No code reads directory contents or proposes departments from folder structure; seed is static and the delegation engine only does regex/keyword intent routing (`orgDelegationEngine.ts:190-414`).
3. **Delegation exists as a renderer-side engine** with keyword routing and optional ACP conversation calls (`orgDelegationEngine.ts:45-580`), but it is **not a verified CEO→department→PM→team pipeline with project-folder boundary enforcement**. `runSimulation()` / “Simulate CEO Delegation” is a hardcoded visual mock (`useOrgStore.ts:372-496`, `OrgCanvasToolbar.tsx:96-107`).
4. **Automation is not implemented as org-scheduled execution.** `OrgCronJob` is a type + empty localStorage list; `toggleCronJob` only flips a flag; no create/edit/delete/pause UI in org pages and no process scheduler wired to `aionui:org-cron-jobs` (`types/organization.ts:134-143`, `useOrgStore.ts:47,124,364-369`; process/common searches returned no org automation scheduler).
5. UI/canvas/state scaffolding and basic CRUD modals exist, but several intended capabilities (folder-content analysis, true PM/team execution model, folder safety boundaries, real org automations, destructive-action confirmation for reset) are absent or unverified.

### Storage / persistence

`useOrgStore.ts` stores org state in **renderer localStorage**:

- Keys: `SCOPE/HIERARCHY/PROJECTS/CONVERSATIONS/CRON_JOBS/VERSION` = `aionui:active-scope`, `aionui:org-hierarchy`, `aionui:org-projects`, `aionui:org-conversations`, `aionui:org-cron-jobs`, `aionui:org-storage-version` (`:42-49`).
- Initial load: `loadStored` JSON-parses from localStorage; if stored version `< ORG_STORAGE_VERSION` it forces blank defaults and overwrites stored hierarchy/projects/conversations/cron jobs (`:89-111`).
- Persists hierarchy/projects on mutations (`:147-150,266-269,...,362`). Conversations/cron jobs persisted in their setters (`:336-341,364-369`).
- `aionui:org-ui` is separate UI prefs in `OrganizationSiderContent.tsx:115-135` (dept sub-tabs).
- **No process/main bridge found** for saving/loading org hierarchy/projects/conversations/cron jobs. `docs/prds/organization-sidebar-audit.md:14,92` also states org state is renderer localStorage (pre-existing design note).

### CEO → dept → team → project routing (real functions)

Implemented in `OrgDelegationEngine` (`orgDelegationEngine.ts`):

1. `executeDirective(userPrompt, targetDeptId?, targetTeamId?, projectId?, useRealExecution=false)` (`:154-579`). Sets `simulationMode = !useRealExecution` (`:161`).
2. **Intent A (dept creation):** regex match on “create/add/new/setup/start/instantiate/build department…” (`:193-232`) returns synthetic creation of `createDepartmentShell(...)` — does **not** analyze folders.
3. **Intent B (team creation):** regex match (`:237-305`) creates `createTeamShell(...)` in matched/targeted/single department.
4. **Target resolution:** explicit IDs, else keyword matching on department name/description or hardcoded domain keywords (`app/software/engineer/dev/code → app|software|engineer|tech`, `video/youtube/media/channel`, `social/tweet/post/marketing`, `coach/health/life/hr`) (`:307-358`). **No LLM classification of folder contents.**
5. **No target dept:** executes at “Root CEO” level via `runOrgAgentStep(rootCeo.ceoAgent, ...)` in real mode or returns canned strategic text in simulation mode (`:360-414`). Root CEO system prompt is hardcoded: `You are the Global Organization CEO. Direct strategic planning, department structuring, and organizational leadership.` (`:379-381`).
6. **With target dept/team:** computes execution folder as `project folder > team folder > department folder` (`:416-418`), resolves first team if unspecified (`:435-459`), logs handoffs, then runs specialists (max 3, `Math.min(...,3)` at `:493`) via `runOrgAgentStep` with `workspacePath = targetProjectPath || team.workspacePath || dept.workspacePath || ''` (`:510-522`). Specialist `systemPrompt` passed as `spec.title || spec.role` (`:516`). No PM agent step, no project-file reads, no folder-boundary checks.
7. **Real agent execution path:** `runOrgAgentStep` (`:76-143`) creates ACP conversation `org-agent-<ts>-<rand>` (`:82`) with `ipcBridge.conversation.create.invoke({ type:'acp', id:convId, name:\`Org: ${agent.name}\`, assistant:{id:agent.canonicalAgentId||agent.id}, extra:{workspace:workspacePath, custom_workspace:true} })` (`:108-118`, create errors swallowed), sends `input: userDirective` (`:120-123`), waits for `responseStream` finish or **8s timeout** (`:125-135`). Returns collected stream text or fallback.
8. **Simulation mode:** `runOrgAgentStep` sleeps 1200ms and returns `[Simulated]...` (`:77-80`). `OrgInspectorDrawer` invokes engine with `useRealExecution=true` (`OrgInspectorDrawer.tsx:196-219`). `OrganizationSiderContent` CEO directive uses `useRealExecution=true` (`OrganizationSiderContent.tsx:166-168`).

### “Simulate CEO Delegation” button

`OrgCanvasToolbar.tsx:96-107` calls `useOrgStore().runSimulation()`. `useOrgStore.runSimulation` (`useOrgStore.ts:372-496`) is a **hardcoded visual simulation**: fixed delays, fixed step messages, node-status color changes on `root-ceo`/first dept/first team. It does **not** call `OrgDelegationEngine`, does **not** create conversations/tasks, and does **not** execute in project folders.

## 9. Top 10 recommended improvements, ranked

1. **Implement folder boundary enforcement (Critical).** Before/inside execution, resolve and validate all target paths against assigned project/team/department roots; block reads/writes outside allowed scope in org layer and enforce again in process/ACP tooling.
2. **Build real folder intake + analysis flow.** Let CEO select a root folder, enumerate/read metadata/content safely, and produce reviewable department/subfolder/project proposals (including “General/unrelated”) with explicit user approval.
3. **Replace heuristic-only delegation with an explicit planning/execution model.** Introduce PM/department/team handoff objects, task decomposition, cross-department splits, clarifying questions for ambiguous requests, and auditable hop logs tied to real agent runs.
4. **Make agent execution context-aware and bounded.** Pass project context (files summary, prior relevant chats, constraints, assigned folder) with size limits; capture changed files/artifacts; use per-role system prompts from editable agent profiles.
5. **Fix destructive UX and data safety.** Add confirmation/undo affordance for “Reset to Blank Canvas”; avoid silent data loss on storage-version bumps by migrating when possible and backing up old payloads.
6. **Implement real org automations.** Create/edit/delete/pause automation records in org UI, bind them to department/project scope, schedule/trigger via the existing scheduler/cron backend, support manual run, store output location, and surface failure state.
7. **Clarify or remove mock simulation affordances.** Rename “Simulate CEO Delegation” to clearly indicate mock telemetry, or gate it behind debug mode; never present it as real delegation.
8. **Add department removal/reassignment and path validation.** Support remove/archive with dependency checks, reassign folders/projects safely, validate absolute/existing paths, and handle moved/deleted folders (F1).
9. **Harden ACP integration.** Do not swallow conversation-create failures; handle assistant availability; make timeout/stream completion explicit; persist execution IDs/results; handle concurrent tasks with queueing or conflict UI (F2/F4).
10. **Add runtime/E2E verification for org workflows.** Automated tests for delegation routing, path safety, automation scheduling, reset confirmation, and UI state/data consistency; current unit coverage (4 files/30 tests) does not exercise end-to-end CEO/delegation/automation behavior.
